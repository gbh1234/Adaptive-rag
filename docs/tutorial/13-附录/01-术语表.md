# 术语表

本术语表汇总全书出现的核心术语，按主题分组。每一条先给出中文名，再给出英文名，最后给出一句话解释。

读者在阅读正文时遇到不熟悉的词，可以回到此处查证。

---

## 一、检索基础

| 术语 | 英文 / 全称 | 一句话解释 |
| --- | --- | --- |
| **向量表示** | Vector Representation | 把一段文本映射成一组固定长度的数字，使意思相近的文本在数字空间里也相近 |
| **嵌入** | Embedding | 生成向量的过程，由嵌入模型完成 |
| **嵌入模型** | Embedding Model | 把文本映射成向量的模型，也叫双塔模型，因为它对查询与文档分别编码 |
| **维度** | Dimension | 向量中数字的个数；本项目的稠密向量为 512 维 |
| **余弦相似度** | Cosine Similarity | 衡量两个向量方向夹角的指标，越接近 1 表示方向越一致 |
| **归一化** | Normalization | 把向量除以自身长度，使其长度变为 1；归一化之后，点积等价于余弦相似度 |
| **稀疏召回** | Sparse Retrieval | 基于词面匹配的召回方式，代表是 BM25 |
| **稠密召回** | Dense Retrieval | 基于向量相似度的召回方式，也叫语义召回 |
| **BM25** | — | 一种关键词打分算法，用词频饱和与逆文档频率平衡长文本与常见词的偏置 |
| **逆文档频率** | IDF，Inverse Document Frequency | 一个词在越少文档中出现，它的权重越高 |
| **切块** | Chunking | 把长文档切成若干短块的过程，切出的单位叫切片 |
| **切片** | Chunk | 一个独立的检索单位，携带内容与来源元数据 |

> 这一组术语是召回层的最小词汇表，后文的混合检索与精排都建立在它们之上。

## 二、检索优化

| 术语 | 英文 / 全称 | 一句话解释 |
| --- | --- | --- |
| **混合检索** | Hybrid Retrieval | 同时使用稀疏与稠密两路召回 |
| **RRF** | Reciprocal Rank Fusion，倒数排名融合 | 按名次而非分数合并多路召回结果的算法 |
| **交叉编码器** | Cross-Encoder | 把查询与文档拼接后联合编码的模型，用于精排，精度高但速度慢 |
| **双塔模型** | Bi-Encoder | 把查询与文档分别编码的模型，用于召回，速度快但精度较低 |
| **精排** | Rerank | 对召回后的候选重新排序，通常由交叉编码器完成 |
| **查询改写** | Query Rewrite | 在检索前把用户问题改写为更适合检索的形式 |
| **Self-RAG** | 自反思检索 | 检索、评分、改写、再检索的迭代循环 |
| **多跳检索** | Multi-hop Retrieval | 一次检索不足以覆盖时，分多次检索逐步补全证据 |

> 这一组术语回答的是"如何把召回做得更准"。

## 三、上下文与决策

| 术语 | 英文 / 全称 | 一句话解释 |
| --- | --- | --- |
| **上下文窗口** | Context Window | 模型单次能处理的输入长度上限 |
| **引用** | Citation | 答案中标注的来源，指向具体的切片 |
| **短期记忆** | Short-term Memory | 当前会话的完整消息列表 |
| **长期记忆** | Long-term Memory | 压缩后的摘要与滑动窗口 |
| **三级压缩** | Three-level Compression | 按预算利用率分档执行的压缩策略，分为软截断、硬压缩与自动压缩 |
| **意图识别** | Intent Classification | 把用户问题归到预设类别的过程 |
| **复杂度路由** | Complexity Routing | 根据意图与查询特征决定处理策略的过程 |
| **覆盖层** | Intent Overlay | 一组针对稳定中文歧义的高置信短语规则，用于纠偏 |

> 这一组术语处理"给模型看什么"与"把问题送到哪条路径"。

## 四、五策略

| 策略 | 一句话解释 |
| --- | --- |
| **DIRECT** | 直接回答，不检索，用于问候与闲聊 |
| **SINGLE** | 一次混合检索，用于单条政策问答 |
| **MULTI** | Self-RAG 多跳检索，用于含多个约束的问题 |
| **AGENT** | 规划加工具执行，用于查单、物流、取消等请求 |
| **REFUSE** | 边界拒答，用于越界或注入请求 |

> 五条策略覆盖从"直接答"到"明确拒答"的完整谱系。

## 五、工作流与安全

| 术语 | 英文 / 全称 | 一句话解释 |
| --- | --- | --- |
| **LangGraph** | — | 一个状态机框架，用于把处理流程拆成节点与边 |
| **状态** | State | 在流程中流转的数据结构；本项目的 `AgentState` 是替换式的 `TypedDict` |
| **节点** | Node | 流程中的一个处理环节，例如意图识别或检索 |
| **条件边** | Conditional Edge | 根据状态决定下一个节点的边 |
| **工具** | Tool | 系统可调用的外部能力，按风险分为只读、写入、破坏性与外部四类 |
| **Skill** | — | 一组按场景组织的工具与步骤，用于收缩规划器的工具目录 |
| **MCP** | Model Context Protocol | 一种工具接入协议，本项目让 MCP 工具与本地工具共用同一套接口 |
| **HITL** | Human In The Loop，人在回路 | 高风险写操作在执行前必须得到用户确认 |
| **待确认动作** | ActionProposal | 写操作的提案，包含动作标识、工具名、参数与风险等级 |
| **幂等** | Idempotency | 同一操作重复执行只产生一次效果；本项目用参数指纹与幂等键实现 |
| **参数指纹** | Fingerprint | 工具名与参数序列化后的哈希值，用于识别重复与冲突 |
| **护栏** | Guardrail | 拦截恶意输入与不实输出的机制 |
| **Prompt Injection** | 提示词注入 | 通过输入诱导模型忽略原有指令的攻击方式 |
| **忠实度** | Faithfulness | 答案被证据支撑的程度，由裁判模型判断 |
| **幻觉率** | Hallucination Rate | 忠实度判负的比例 |

> 这一组术语把"流程如何编排"与"动作如何被约束"分开来看。

## 六、工程与评测

| 术语 | 英文 / 全称 | 一句话解释 |
| --- | --- | --- |
| **降级** | Fallback | 某依赖不可用时退回更弱但可用的能力 |
| **全抖动** | Full Jitter | 把重试等待时间随机化，避免多实例同时重试 |
| **trace_id** | — | 贯穿一次请求全部环节的追踪标识 |
| **P50 / P95** | — | 延迟的分位数，P50 是中位数，P95 表示 95% 的请求快于该值 |
| **Precision@1** | — | 排在第一位的文档是否相关 |
| **Recall@3** | — | 前三条是否覆盖全部相关文档 |
| **MRR** | Mean Reciprocal Rank，平均倒数排名 | 第一个相关文档排名的倒数 |
| **消融实验** | Ablation | 一次去掉一项技术，观察成绩变化，用于分离各项技术的独立贡献 |

> 这一组术语是"上生产"与"拿证据"两部分的公共词汇。
